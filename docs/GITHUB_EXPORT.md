# GitHub 安全导出说明

本项目导出到 GitHub 的是**应用源码、依赖清单与数据库结构定义**，不会自动包含运行中的数据库记录、浏览器本地记录或平台运行时密钥。

## 用户数据边界

当前版本的“记录”功能保存在每位用户自己的浏览器 `localStorage` 中；这些内容不在项目目录内，因此不会被 Git 提交或导出到 GitHub。此前托管环境中的数据库数据也独立于源码仓库，GitHub 导出不会复制数据库内容、用户账户或历史记录。

项目源码只引用运行环境提供的变量名称，例如 `VITE_FRONTEND_FORGE_API_KEY` 与 `DATABASE_URL`，不写入变量值。`.gitignore` 进一步排除了环境配置、私钥、服务账号凭据、本地数据库、日志和平台本地配置。请不要为了便于部署而把令牌、密码、数据库连接串或导出的用户记录写进代码或提交到仓库。

## 已完成的导出前审查

已对受版本控制的源码进行凭据、连接串、邮箱和用户标识扫描。扫描命中的 `server/_core/*`、`server/db.ts`、`server/media.ts`、`server/storage.ts` 与 `client/src/components/Map.tsx` 均只读取**运行时环境变量名称**或使用平台代理；未发现写入源码的变量值、生产连接串或私钥。`package.json` 中的命中来自依赖包名称；`server/auth.logout.test.ts` 与 `template.json` 中的邮箱、用户信息均为 `sample@example.com`、`sample-user` 等测试样例，并非真实账户或用户记录。当前工作区也没有受 Git 跟踪的本地数据库、日志、环境配置或实际用户决策导出文件。

最终仓库扫描确认：**实际密钥格式或带密码连接串为 0 项，受 Git 跟踪的本地数据或环境配置文件为 0 项**。剩余的非样例邮箱命中仅位于 `package.json`、`pnpm-lock.yaml` 与 `template.json` 的依赖元数据或其模板副本中；其中 `i@izs.me` 是第三方依赖元数据，不属于本项目用户数据。该结论仅覆盖当前受 Git 跟踪的项目文件；部署平台中的运行时 Secrets 与生产数据库仍须保持在平台受控设置中。

## 推荐的导出方式

建议先创建 **Private（私有）** GitHub 仓库，并仅邀请确有维护需求的协作者。随后在项目管理界面的 **Settings → GitHub** 中连接 GitHub，并选择新建或导出至该私有仓库。导出前应在 GitHub 的文件预览中确认以下内容没有出现：

| 不应出现在仓库中的内容 | 正确处理方式 |
| --- | --- |
| `.env`、数据库连接串、API 密钥或访问令牌 | 仅在部署平台的 Secrets 设置中配置 |
| 用户决策记录、数据库备份或 CSV 导出 | 保留在受控存储中，按需加密备份 |
| 私钥、服务账号 JSON、证书文件 | 通过密钥管理工具或平台 Secrets 注入 |
| 开发日志、浏览器调试记录 | 保持本地，勿提交 |

## 导出后的保护措施

导出完成后，请保持仓库私有，并在 GitHub 开启双重验证、限制协作者权限和启用分支保护。若未来接入外部数据库或自行部署，应在该服务中单独设置最小权限账户、TLS 连接与定期备份；不要把生产数据作为仓库文件管理。
